# 拾趣 · Sharey99 的个人小站

把好用的收藏，把有趣的分享。

这里整理好用、好玩的网站，分享有明确来源的资源链接，记录游戏与生活的攻略，也给自己的思考、随笔和学习笔记留一个位置。

**计划访问地址：[sharey99.github.io](https://sharey99.github.io/)**（启用 GitHub Pages 且部署成功后生效）。

## 小站里有什么

| 分类 | 内容 |
| --- | --- |
| 好用网站 | 效率工具、图像编辑、学习文档及实用网页服务 |
| 有趣网站 | 网页小游戏、互动实验、声音与视觉体验 |
| 资源书架 | 书籍、课程、视频、文档的官方或授权入口，以及有公开传播权的文件 |
| 游戏攻略 | 玩法、路线与游戏心得，注明平台、版本及剧透范围 |
| 人生攻略 | 生活实践、个人复盘与经验，说明适用前提 |
| 随笔笔记 | 自己悟出的道理、读书笔记、学习记录与尚未想明白的问题 |

本版内置 **8 个外部入口、3 篇示例文章，共 11 个条目**。标为“示例文章”的内容用于展示排版和阅读功能，不代表站主实际经历或观点。请替换为自己的内容、日期和类型，也可以直接删除示例。

“拾趣”为本版本暂定站名，可自行修改。

## 哪些适合放，哪些需要授权

下面的发布建议以你拥有相关权利、符合适用规则为前提。公开可访问、免费、非营利或标明来源，都不是自动转载许可。

| 内容 | 建议发布方式 | 注意事项 |
| --- | --- | --- |
| 自己的笔记、心得、攻略 | 直接写在站内 | 不含他人隐私、保密信息；职务或受托成果先核对权利归属 |
| 网站、作者文章和视频 | 写自己的简介，链接原作者或官方页面 | 不绕过付费、登录等访问限制，不冒充来源 |
| 自制视频 | 优先发布到视频平台，再贴观看链接 | 配乐、画面、配图也需有相应使用权 |
| 有权公开传播的 PDF、EPUB 和资料 | 小文件可提供附件，大文件用合适的平台 | 保留授权依据，核对文档内素材的权利 |
| 获得转载授权或开放许可的作品 | 按具体许可转载或分发 | 核对署名、改编、再分发、商业使用等条件 |
| 公版书籍 | 优先链接可信来源 | 核对地区；译本、注释、插图或整理版本可能有独立版权 |
| 读书摘录和评论中的引用 | 以自己的理解为主，必要时适当引用并注明作者与作品 | 不用大段摘录替代原作；合理使用需结合具体情形判断 |
| 游戏截图、演示与素材 | 写自己的攻略，使用符合发行商政策的素材 | 不自动免授权；留意版本与剧透 |

### 本站不收录

- 未经授权的付费电子书、扫描书、课程搬运、影视和音乐文件。
- 盗版游戏、破解软件、盗用激活码、账号共享或泄露数据库。
- 明知用于提供上述侵权内容的网盘地址、种子、磁力链接和下载合集；只放链接也不自动免责。
- 他人身份证、私人聊天、未获同意的照片和联系方式，以及未授权公开的公司、客户资料。
- 恶意文件、钓鱼页面及其他违法内容。

买过一本电子书或一套课程，一般不等于取得向公众传播的权利。“仅供学习”“侵删”也不能替代授权。授权不明时，先只记录书名、作者和官方购买或阅读入口。

这些是本站收录原则，具体作品仍需核对适用法律和许可。关于权利归属、公开传播、适当引用，参见[国家版权局发布的《中华人民共和国著作权法》](https://www.ncac.gov.cn/xxfb/flfg/flfg_532/202103/t20210309_50530.html)。

### 视频、书籍、文件怎么放

- **别人发布的视频**：保存原作者在正规平台上的观看链接，不下载搬运；如需嵌入播放器，先确认平台规则。本版不预加载第三方播放器。
- **自己的视频**：上传至合适的视频平台，再添加链接，避免用 Pages 存大视频。
- **别人出版的书籍**：分享自己的书评、笔记及出版社或授权平台链接；未获许可不提供整本 PDF/EPUB。
- **自己编写且有权公开的文件**：小文件可放在仓库的 `files/` 中；大文件放到你有权使用的存储平台，再添加链接。
- **免费或公版资源**：保留来源并查看许可。Project Gutenberg 主要基于美国版权状态选书，不能据此认为每个版本在所有地区都可自由传播。[该项目版权说明](https://www.gutenberg.org/policy/permission.html)

## 文件与功能

只上传下面两个文件，就可以运行这个版本：

```text
sharey99.github.io/
├── index.html     # 首页，包含样式、内容和交互
└── README.md      # 仓库介绍、分享原则和维护说明
```

以后需要时再自行创建 `files/` 文件夹，放有权公开的小附件。

- 无需构建、安装依赖或购买服务器；`index.html` 也可直接双击预览。
- 支持电脑和手机布局、关键词搜索、分类筛选、排序及“随便逛逛”。
- 站内文章以弹窗阅读，支持键盘操作和 Escape 关闭。
- 搜索覆盖标题、简介、标签、分类、类型和站内正文；不搜索外部网页或附件正文。
- 无账号、评论、后台、上传、广告或统计功能；不保存搜索词。
- 不依赖外部字体、图片或 JavaScript 库，外链由访客主动点击打开。
- 浏览器不是后台编辑器。修改本地文件后，需要重新提交到 GitHub 才会更新线上网站。

## 第一次发布：上传两个文件

1. 打开 `sharey99` 账号下的 `sharey99.github.io` 仓库。
2. 在 **Code** 页选择 **Add file → Upload files**。
3. 上传 `README.md` 和 `index.html`，已有 README 时用本版替换。文件要在仓库最外层，不要额外套一层文件夹。
4. 点击 **Commit changes** 提交。
5. 打开 **Settings → Pages**。
6. **Source** 选 **Deploy from a branch**，**Branch** 选 `main`，目录选 `/ (root)`，点击 **Save**。
7. 等待部署完成，打开 [https://sharey99.github.io/](https://sharey99.github.io/)。

发布可能需要几分钟，GitHub 官方说明更新可能需要最多约 10 分钟。[发布教程](https://docs.github.com/en/pages/quickstart)

如果打不开，先看 **Actions** 中部署是否成功，再确认首页是小写 `index.html` 且位于 `main` 分支最外层。不要保存为 `index.html.txt`。

本地“临时文件”里的截图、脚本和检查记录不需要上传。

## 怎么添加收藏

用代码或纯文本编辑器打开 `index.html`（不要用 Word），搜索：

```html
<script id="content-data" type="application/json">
```

下方 `[...]` 中是全部条目。只编辑这段数据，通常无需改样式和交互脚本。

### 添加外部链接

复制现有条目，按下面格式填写。示例链接用于说明格式，添加真实收藏时替换为对应来源页面。

```json
{
  "id": "my-useful-link",
  "category": "tools",
  "title": "我的网页学习入口",
  "description": "用自己的话说明它有什么用、适合谁，以及需要留意什么。",
  "tags": [
    "学习",
    "网页"
  ],
  "url": "https://developer.mozilla.org/zh-CN/",
  "icon": "code",
  "tone": "blue",
  "date": "2026-10-30",
  "kind": "官方入口"
}
```

### 添加自己的文章

省略 `url`，改用 `body`。标题和正文为纯文本，不执行 HTML 或 Markdown。

```json
{
  "id": "my-first-note",
  "category": "notes",
  "title": "写下我的第一篇笔记",
  "description": "用一两句话写这篇笔记的主题。",
  "tags": [
    "随笔",
    "记录"
  ],
  "icon": "note",
  "tone": "peach",
  "date": "2026-10-30",
  "kind": "个人笔记",
  "body": [
    {
      "heading": "发生了什么",
      "text": "在这里写下自己的真实记录。"
    },
    {
      "heading": "我的理解",
      "text": "在这里写下自己的思考，以及仍不确定的地方。"
    },
    {
      "heading": "下一步",
      "text": "在这里写下准备如何实践或核实。"
    }
  ]
}
```

请用真实日期替换示例日期。“最近收录”按 `date` 倒序排列，同一天保留条目原有顺序。

### 添加有权公开的附件

先将文件上传到仓库的 `files/` 中，再把条目的 `url` 改为：

```json
"url": "./files/my-reading-notes.pdf"
```

其他标题、简介、分类等字段仍需保留。文件由浏览器打开，是否预览或下载取决于格式与浏览器。

文件名推荐用英文字母、数字、短横线；大小写须与真实文件一致。页面只接受 HTTPS 外链和 `./files/` 下的附件相对路径，不接受脚本链接或 `../` 路径。

### 字段速查

| 字段 | 方法 |
| --- | --- |
| `id` | 唯一编号，只用小写英文字母、数字、短横线，不能重复 |
| `category` | 六个分类 id 之一，见下表 |
| `title` / `description` | 标题与简介，纯文本 |
| `tags` | 字符串数组，例如 `["读书", "思考"]` |
| `url` | 外链或附件路径；站内文章省略 |
| `body` | 文章段落数组，每段 `text` 必填，`heading` 可省略 |
| `date` | `年-月-日`，例如 `2026-10-30` |
| `kind` | 展示标签，如“官方入口”“个人笔记”“原创攻略” |
| `icon` | `pen`、`spark`、`play`、`image`、`radio`、`book`、`game`、`code`、`leaf`、`note` |
| `tone` | `green`、`blue`、`peach`、`purple`、`yellow` |

| 分类 id | 名称 |
| --- | --- |
| `tools` | 好用网站 |
| `fun` | 有趣网站 |
| `resources` | 资源书架 |
| `games` | 游戏攻略 |
| `life` | 人生攻略 |
| `notes` | 随笔笔记 |

维护要点：

- 每两个条目之间用英文逗号分隔，最后一项末尾不加逗号。
- 属性名和字符串使用英文双引号，不在 JSON 中写注释。
- 字符串内部的英文双引号用 `\"`，换行可用 `\n`。
- 正文不要直接写 HTML 的 script 结束标签；必要时把 `<` 写成 `\u003c`。
- 页面提示“收藏内容暂时无法显示”，通常是 JSON 格式或字段错误，先检查刚修改的条目。
- 站名、关于本站、分享原则、网页标题和简介直接写在 HTML 中，搜索对应原文即可修改。
- 如果改了用户名，记得替换页面和本文里的 `sharey99` 地址。
- 当前文章在弹窗中阅读，没有独立网址；以后文章增多可扩展为独立页面。

- 原创内容不默认授予整篇转载权；第三方内容仍按其权利人的许可使用。
- 没有 LICENSE 文件不等于没有版权。本版没有替站主选择全站开源或文章转载许可；需要开放授权时，可以分别为代码和文章选择许可。

- 纠错入口为仓库 [GitHub Issues](https://github.com/sharey99/sharey99.github.io/issues)。请确认 **Settings → General → Features → Issues** 已启用；也可自行改成愿意公开的邮箱。
- 反馈通常公开，避免填写身份证、住址等敏感信息。版权疑问可提供页面、来源与权利说明。

## GitHub Pages 的边界

这是个人内容站和导航站，不适合作为视频存储或大型下载合集。当前 GitHub Pages 发布站点上限为 **1 GB**，每月带宽有 **100 GB 软限制**；也不允许作为主要用于商业交易或商业 SaaS 的免费托管服务，不应处理密码和信用卡等敏感交易。[Pages 使用限制](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)

通过浏览器上传的单个文件不能超过 **25 MiB**，普通 Git 仓库会阻止超过 **100 MiB** 的文件。它们是不同环节的限制，并不意味着小于上限的文件一定适合上传。[文件大小说明](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)

若以后需要登录、数据库、收费或大文件分发，需另选服务；当前两个文件没有这些功能。版权侵权内容也可能依 [GitHub DMCA 政策](https://docs.github.com/en/site-policy/content-removal-policies/dmca-takedown-policy) 被要求移除。
